## 4. 发现的可视化问题与修复（BUG-08～11）

### BUG-08 输入控件类型全部失效（13 处）
- **现象**：到货日期、报价截止、品位、金额等本应是日期/数字控件的输入，实际全部渲染为纯文本框；用户可输入任意文本，错误要到提交后才暴露。
- **根因**：`frontend/js/ui.js` 的 `UI.input(type, value, props)` 未把 `type` 赋给 input 元素。
- **修复**：`function input(type, value, props) { const el = h('input', ...); if (type) el.type = type; ... }`
- **回归**：S03/S04 中期望到货日期渲染为 `date`、报价截止渲染为 `datetime-local` 控件，PASS。

### BUG-09 品位字段"牌号"文案错位 → 需求保存必失败
- **现象**：新建需求添加明细后保存必失败，toast 报"数值格式错误：grade"。
- **根因**：前端品位字段用文本框 + 「牌号」文案引导用户输入文本（如 `ZH-1`），而数据库 `biz_demand_item.grade` 为 NUMERIC(5,2) 数值品位（百分数，如 62.00），后端 `_num()` 校验必然拒绝。
- **修复**：`frontend/js/pages/demand.js` 品位改数字输入 + 「品位(%)」标签；`trade.js`/`order.js`/`admin.js` 展示文案同步（列表列名、详情、默认品位设置）。
- **回归**：S03 输入 62.1 保存（toast「已创建草稿」）+ 提交（toast「已提交」）PASS；E2E 全链路 97/97 PASS。

### BUG-10 合同页永远空白（静默失败·关键缺陷）
- **现象**：「合同」菜单页无表格、无空态、无网络请求、无任何报错——页面永久空白。
- **根因**：`frontend/js/pages/order.js` 的 `Pages.contract` 定义了 `load()`（L183-199）与 `detail()`（L248-270），但函数结尾**从未调用 `await load()`**。
- **诊断过程**（方法论沉淀）：
  1. 先疑时序竞争，加 12s 列表等待仍失败；
  2. 编写一次性探针（包装 `window.fetch` 记录 start/done/fail 生命周期 + 抓取 `#page` innerHTML + `performance.getEntriesByType('resource')` + console 日志）；
  3. 探针结论：`/contracts` 的 fetch **从未发出**、`window.__log` 为空、路由正常完成、console 无错误——典型的"定义了加载函数但没调用"静默失败。
- **修复**：函数结尾补 `await load();`。
- **回归**：S16 合同列表出现待签行，需方签署成功，PASS。
- **教训**：①`performance entries` 不包含未完成的 fetch；②console 无 SEVERE ≠ 无缺陷；③`await load();` 文本搜索曾误匹配到 `Pages.order` 结尾造成误判，需结合函数边界确认。

### BUG-11 供应商结算管理页永远空白（同 BUG-10 模式）
- **现象**：中矿登录「结算」页列表空白，无「供应商确认」按钮。
- **根因**：`frontend/js/pages/settle.js` 供应商分支（L173 起）定义 `load()`/`acts()`/`detail()` 但结尾未调用 `await load()`（钢厂工作台分支有调用，故仅供应商侧空白）。
- **修复**：结尾补 `await load();`；并**系统化排查全部 17 个 Pages 函数**，确认无同类"定义未调用"遗漏。
- **回归**：S21 供应商结算列表出现结算单与「供应商确认」按钮，PASS。

## 6. 遗留观察项（不阻断，已记录）

1. **需求明细保存失败时主表不回滚**：运行3 中品位缺陷导致明细保存失败，但需求主表已写入，留下 DRAFT 残留数据（低严重度）。建议后端将明细保存纳入同一事务。
2. **合同页/揭示弹窗此前无 loading 指示**：数据加载期间页面短暂空白无过渡提示。随 BUG-10/11 修复后页面即时渲染，现有数据量下体验正常；如后续数据量增大可补充骨架屏/loading。
3. **测试专用账号**：13900000001（中矿）/13900000002（普阳）为 UI 检测专用账号，与 3.4 节 138 号段演示账号相互独立。
4. **S09 到期依赖**：揭示要求报价截止已过，检测脚本内置"将未到期询价 deadline 提前 5 分钟"的模拟步骤（`docker exec` psql），复跑无需人工干预。
