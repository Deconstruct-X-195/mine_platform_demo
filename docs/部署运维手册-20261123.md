## 1. 架构与隔离

请求链路：

```
浏览器 ──> Nginx :18000 ──> Waitress 127.0.0.1:8000 (mine-app) ──> PostgreSQL 127.0.0.1:5432 (mine-pg)
定时任务：mine-jobs.timer 每小时触发 mine-jobs.service（oneshot，应用内 MINE_DISABLE_JOBS=1 不重复跑）
```

与既有项目（词元绽放 sco、kunlun-test 等）**完全隔离**，本次部署未改动任何既有配置：

| 维度 | 本项目 | 说明 |
| --- | --- | --- |
| 目录 | `/opt/mine_platform` | 独立目录树，不与 /var/www/sco 等重叠 |
| 端口 | 18000（对外）/ 8000（应用）/ 5432（数据库） | 全部为新端口；应用与数据库仅监听 127.0.0.1 |
| 系统用户 | mine（应用）/ postgres（数据库） | 独立用户 |
| systemd | mine-pg / mine-app / mine-jobs.timer | 独立命名，均已 `enable` 开机自启 |

| Nginx | `/etc/nginx/conf.d/mine.conf`，listen 18000 | 独立 server 块 |

## 3. 日常操作命令

`ssh gpu-node` 以 root 登录后执行。

### 3.1 服务启停

```bash
systemctl start mine-app            # 启动应用（Requires 自动带起 mine-pg）
systemctl stop mine-app             # 停止应用
systemctl restart mine-app          # 重启应用（改代码或 env 后执行）
systemctl status mine-app mine-pg   # 查看状态
```

> 注意：停止数据库前建议先停应用（`stop mine-pg` 不会自动停 mine-app，避免应用在库停后持续报错）。

```bash
systemctl start mine-pg             # 单独启动数据库
systemctl list-timers mine-jobs*    # 查看定时任务计划
systemctl start mine-jobs.service   # 手动跑一轮定时任务
```

### 3.2 日志查看

```bash
journalctl -u mine-app -f              # 应用实时日志
journalctl -u mine-app -n 100          # 应用最近 100 行
journalctl -u mine-app --since today   # 应用今天以来的日志
journalctl -u mine-pg -n 50            # 数据库日志
journalctl -u mine-jobs -n 20          # 定时任务单轮执行日志
tail -50 /var/log/nginx/access.log     # Nginx 访问日志（与其他站点共用，按端口/路径过滤）
```

### 3.3 Nginx

```bash
nginx -t && systemctl reload nginx    # 改 mine.conf 后先测语法再 reload
```

### 3.4 代码更新（离线流程）

服务器完全断网，更新流程：本地 `git archive` 打源码包 → `scp` 上传 → 服务器解压覆盖 `/opt/mine_platform/app` → `systemctl restart mine-app`。
依赖有变更时，需在本地按目标平台 `pip download` 新 wheels 后 scp 离线安装到 venv。

## 4. 常见问题排查

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 页面/接口超时打不开 | 安全组未放行 18000 | 阿里云控制台 → ECS 安全组 → 放行 18000/tcp |
| 页面打不开（内网正常） | mine-app 未运行 | `systemctl status mine-app`；`journalctl -u mine-app -n 50` |
| Nginx 返回 502 | 应用进程挂了或内存超限被杀 | `journalctl -u mine-app -n 50` 找 OOM/Killed 记录，`restart mine-app` |
| 登录报"用户名或密码错误" | 密码不对（code 40001 为正常业务响应） | 用 manage.py reset-admin-password 重置（见 §5） |
| 接口报数据库相关错误 | mine-pg 未运行 | `systemctl status mine-pg`；`journalctl -u mine-pg -n 50` |
| 服务频繁被杀 | 内存超 MemoryMax（1.8G 小内存机器） | journalctl 确认 oom-kill；评估加 swap 或降低并发 |
| 磁盘不足 | 上传文件 / pgdata 增长 | `df -h`；`du -sh /opt/mine_platform/*` |
| 端口被占 | —— | `ss -lntp` 查看 18000/8000/5432 监听 |

内存水位参考：部署完成时 mine-pg ≈28M、mine-app ≈35M，整机 available ≈544M，距限额（200M/300M）余量充足。

## 5. 凭据与安全

- 平台管理员账号：`13900000000`。初始密码已于交付时单独告知，**未写入本文档/代码库**；登录后建议尽快轮换。
- 密码轮换（服务器本机交互执行，密码不回显、不落 history）：

```bash
sudo -u mine bash -c 'set -a; . /opt/mine_platform/env; set +a; cd /opt/mine_platform/app && /opt/mine_platform/venv/bin/python manage.py reset-admin-password'
```

- `/opt/mine_platform/env` 含数据库密码与 JWT 密钥：勿外泄、勿提交仓库；轮换 `MINE_JWT_SECRET` 会使全部登录态失效。
- 数据库仅监听 127.0.0.1，pg_hba 强制 scram-sha-256；应用与库均不对外网暴露。
- 附件下载统一走鉴权接口 `/api/v1/files/<file_id>`，无匿名直链。
- 审计：管理员变更写入 sys_operation_log，可用 `python manage.py list-admins` 核对。
