## 二、逐项修复说明

### P0-0 `client_ip()` 无请求上下文守卫（根因）

- **问题**：`client_ip()` 直接访问 `flask.request`，任务线程经 `op_log` 调用即抛 RuntimeError，定时任务全灭。
- **处理方式**：加 `has_request_context()` 守卫，无请求上下文返回 `'SYSTEM'`（与同文件 `send_msg` 的既有守卫对齐）。
- **改动文件**：backend/common.py
- **验证结果**：`run.py --jobs` 实测揭示 3 条到期询价，`sys_operation_log` 审计记录 `ip='SYSTEM'`，任务全程零异常退出（exit=0）。

### P0-A 到期询价自动揭示半提交固化

- **问题**：揭示流程整轮共享事务，询价已置 CLOSED 而报价未标 REVEALED、比价快照未写，半提交随 tick 提交固化，后续定标无快照可用。
- **处理方式**：`_reveal_due_inquiries` 改逐单独立事务——每单成功即 commit、失败 rollback 该单全部变更并 WARN 告警；配合 P1-2 审计原子与第 31 项重锁防线。
- **改动文件**：backend/jobs.py
- **验证结果**：`--jobs` 实测揭示 #49/#52/#54 三单，落库均为 `status=CLOSED 且 reveal_snapshot 非空`（无半提交），`reveal=N(fail 0)` 无 WARN。

### P0-B 订单 48h 超时失效半提交固化

- **问题**：订单置 CANCELLED 但中标报价未回退、询价未重开、需求 deal_qty 未回退、无通知。
- **处理方式**：拆分 `_expire_one_order`，`_expire_orders` 逐单独立事务（同 P0-A 模式）。
- **改动文件**：backend/jobs.py
- **验证结果**：`--jobs` 实测 `expire=0(fail 0)`（当前库无到期样本，路径执行无误）；回退逻辑本身由 e2e_agg_flow G1-G4（关闭归集订单：锁定量释放/需求回退/站内信）与 e2e_full_chain F 系列覆盖，44/44、94/94 全过。

### P1-1 jobs 异常吞错（P0 固化通道）

- **问题**：逐单 `except Exception: print_exc()` 吞错后继续，半提交随 tick 提交且无人告警。
- **处理方式**：三处任务循环统一 `rollback 该单 + WARN 打印 + failed 计数`，tick 汇总行输出 `(fail N)`。
- **改动文件**：backend/jobs.py
- **验证结果**：`--jobs` 实测 fail=0、无 WARN 输出；修复期间人为制造失败场景（并发抢先/状态漂移）均正确回滚并计数。

### P1-2 transition 审计与状态非原子

- **问题**：transition 先 UPDATE 后 op_log，两者非原子；任务路径直接固化"状态已变、无留痕"。

### 第 31 项 逐单 commit 释放扫描锁 → 并发重复处理窗口

- **问题**：P0-A/B 修复引入：扫描行锁（FOR UPDATE SKIP LOCKED）随逐单 commit 释放，并发任务源可能重复处理同一单。本地实测：双 tick 并发下询价 #52 被重复揭示，产生两条 SENT->CLOSED 审计留痕（最终数据一致但审计重复，若揭示触发通知则会重复打扰）。
- **处理方式**：处理每单前对该单 `FOR UPDATE` 重锁并重读状态，状态已流转即 rollback + 幂等跳过（jobs 模块 docstring 同步说明双保险模型）。
- **改动文件**：backend/jobs.py
- **验证结果**：`--jobs` 双轮实测：#54 第一轮揭示 1 次（fail 0），第二轮 reveal=0 幂等跳过；#54 审计 `audit_rows=1` 唯一。

### 第 32 项 `run.py --jobs` 进程内双 tick + 退出噪音

- **问题**：`app = create_app()` 在 run.py 顶层执行，`MINE_DISABLE_JOBS` 未设时 create_app 启动应用内任务线程 → `--jobs` 独立任务进程内"线程 run_loop + run_once"双 tick 并发（正是触发第 31 项窗口的实况）；另进程退出时 psycopg_pool `__del__` 打印 `PythonFinalizationError` 异常栈（退出码不受影响，但定时任务日志每轮留噪音）。
- **处理方式**：run.py 在 import backend 之前对 `--jobs` 参数设 `MINE_DISABLE_JOBS=1`（独立任务进程自身就是执行体）；单轮执行完成后显式 `close_pool()`（db.py 新增）。
- **改动文件**：run.py、backend/db.py
- **验证结果**：`--jobs` 每次运行仅单 tick（单行 reveal/expire 汇总输出）、退出干净无异常栈、exit=0；修复后复跑三套后端回归确认无破坏。
