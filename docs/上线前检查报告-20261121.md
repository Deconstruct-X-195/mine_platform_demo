## 五、已知缺陷清单（书面化）

1. **P1-1** 登录限流键未取真实 IP（见 §3）——反代部署后限流语义失真。
2. **P2-1** 附件下载 IDOR：`GET /files/<id>` 不校验文件与请求者的业务归属。
3. **P2-2** 密码重置后固定为 `demo123456`。
4. **P2-3** 结算 API 为简化实现（2 处 TODO），UI 已下线，API 由 full_chain T17-T19 覆盖。
5. **P2-4** 钢厂询价页"引入需求管理"入口点击返回 40301（旧功能入口未摘除）。
6. **P2-5** PROJECT_GUIDE.md 3 处过时描述。
7. **架构约束** 任务与 Web 同进程：定时任务卡死会拖垮服务。已备拆分方案（`MINE_DISABLE_JOBS=1` + `python run.py --jobs` systemd timer）；**多实例部署时任务进程必须单实例运行**（无分布式锁，重复执行会重复扫描告警）。
8. **容量边界** waitress threads=8，压测实测单机 ~200 QPS、p95 263ms；连接池 min2/max10，高并发下 DB 连接是二级瓶颈。
9. **测试副作用**（仅测试库数据，无业务影响）：ui_e2e 每轮运行会归集/询价一批 3000t 演示需求并软删旧候选；agg id=1(13000t INQUIRING)、agg 11(已成单) 等为历史遗留演示数据，生产库不受影响。

### 本次 ui_e2e 修复过程发现（测试脚本问题，非产品缺陷，记录备查）

- 需求池不过滤已归集明细：旧行随归集单软删/状态变化呈现不同形态，测试改按"最新需求单号"定位（产品可考虑池中行增加已归集标识一致性，非必须）。
- 平台代发询价弹窗"期望到货日"默认 `today+18`：早于常见报价到货日时供方报价会被 40001 拦截——运营使用时需注意将期望到货日设置到报价到货日之后（交互合理性观察项）。
- 比价快照弹窗按钮文案为"确认报价"（非"认可"），自动成单 toast 为"全员认可，已自动锁货锁价生成订单"。

## 六、回滚方案（书面化）

1. 代码回滚：`git checkout <上一发布 tag/commit>` → 重建 venv/重启 systemd；数据库 schema 变更前先 `pg_dump`（deploy 脚本内置 dump 步骤），回滚时先 restore dump 再起旧版本。
2. 配置回滚：systemd EnvironmentFile 保留上一版副本，回滚即换回。
3. 数据回滚：以备份快照为界（见清单 9 的恢复演练），仅回滚业务脏数据不整库回退时，用 dump 的单表 restore。
4. 演练：部署脚本落地后，先在生产预演一次"部署→回滚→再部署"，确认窗口期 < 5 分钟。

## 七、部署后必做验证（对应指导 §5.1）

1. 服务层：kill 进程自动拉起；重启后自启（systemd）。
2. 应用层：`/health` 200；HTTPS 证书链有效、HTTP 301 跳转。
3. 功能层：管理员账号登录 → 三端各抽查关键页（钢厂/供应商/平台）。
4. 数据层：页面时间与真实时间对照（MINE_PG_TZ 语义，防 8 小时偏差复发）；备份任务实际跑过一次。
5. 安全层：匿名访问管理接口 401/403；A 角色访问 B 角色数据被拒；非法 payload（SQL 引号/超长串/越权 ID）实测；**登录失败限流在反代后实测**（对应 P1-1）；默认/演示密码全部已改。
6. 性能层：核心接口 < 500ms；10~50 并发冒烟无 5xx。
7. 日志与监控：日志落盘且轮转生效；告警触发一次（如已接通）。
8. 回滚演练：实际回退一次确认可行。
