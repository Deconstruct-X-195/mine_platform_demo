## 4. 异常情况与处置（实测记录）

### 异常一：UI 检测 S24「console 错误收集」FAIL（23/24）

- **现象**：S01~S23 全部通过，S24 断言失败——浏览器 console 记录 `GET /api/v1/bargains?quoteId=7 - 401 UNAUTHORIZED`。
- **定位**（API 直连复现 + CDP 网络日志 + 代码走查）：供方在议价工作台点击「接受」后触发 `onChanged() → App.route()` 列表重渲染；测试脚本在同一步随即登出并清空 token，重渲染循环中第一张卡片的议价轮次请求（`GET /bargains?quoteId=N`）在 token 清除后发出 → 401。前端 `roundsPanel` 对该请求有 `.catch()` 兜底（卡片显示「轮次加载失败」），页面正常跳转登录页，**业务流程不受影响**。
- **结论**：测试脚本与页面异步重渲染之间的**登出竞态**，非产品缺陷。
- **处置**：修复 `tests/ui_e2e.py` 的 `logout()` 辅助函数，登出前等待 1.5s 使重渲染在途请求完成。复测后原 401 消失。

### 异常二：S15 订单详情渲染 FAIL + S24 网络类错误（22/24）

- **现象**：S15 点击「详情」后弹窗未渲染；S24 console 记录 `GET /orders/12 - net::ERR_NO_BUFFER_SPACE` 与 `api.js Uncaught TypeError: Failed to fetch`。
- **定位**：`ERR_NO_BUFFER_SPACE` 为浏览器连接缓冲耗尽。当日库内累计 **15+ 家 E2E 残留企业与数十条业务单据**，议价工作台/订单列表页每次渲染需对大量卡片发起成串请求，叠加脚本轮询造成短连接风暴，触发环境级瞬态故障。
- **结论**：**历史测试残留数据引发的资源耗尽瞬态**，非产品缺陷（干净基线复测 24/24 即为直接证据）。
- **处置**：按 FAQ Q3 思路重置数据库至种子基线（TRUNCATE 30 张表 → `init_schema + seed` → 6 账号登录验证），复测通过。已将「UI 专项检测连续失败且 console 报网络类错误时，先重置数据库再排查」写入《系统使用说明》§5.4。
