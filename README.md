## 功能特性

### 业务主线

- **平台需求归集集采线（主线）**：钢厂提交需求 → 平台脱敏归集 → 平台代发询价（此时才通知供应商）→ 密封报价 → 揭示生成比价快照 → 钢厂逐单评审认可/不认可（必填理由）→ **全员认可自动成单**（系统自动锁货锁价生成聚合订单，各钢厂份额写入订单成员明细）→ 供应商订单确认 → 各钢厂提交提货计划 → 运营制定运输方案与分段运单 → 履约跟踪 → 归档导出；任一钢厂不认可则询价转「反馈待处理」，运营端可重新询价或按份额手动定标（兜底）
- **钢厂议价定标工作台**：四阶段流程步骤条（已揭示待议价 → 议价中 → 已定标 → 反馈待处理），支持自发询价的比价、多轮议价（一方接受其余轮次自动失效）与定标

### 交易全流程

- **需求申报**：草稿/提交/撤回/重提（版本+1）/关闭；提交后关键字段锁定；供应商仅见脱敏信息（品种/数量/交货区域/期望月份），接口层即不返回钢厂名称与价格意向
- **密封报价**：截止前不可揭示；改价版本留痕；揭示生成比价快照（按价格升序固化）；报价附件上传
- **询价历史**：按轮次只读追溯每一轮询价、全部报价与钢厂反馈；供应商端再次被邀请时展示**历史轮次参考**（当前轮次、各轮询价单号、我的上轮报价、钢厂反馈理由）
- **订单确认与提货计划**：供应商 48h 内确认订单（超时订单自动失效，并回退归集锁定量与需求状态）；每家钢厂提交提货计划（开始提货日期 + 日提货吨数），全部提交后订单自动转「待制定运输方案」
- **运输与物流**：运输方案（铁路直达/公铁联运/汽运直达，公铁联运必填中转站，起运地限黄骅港/天津港，预计船到港时间与运费必填，分段计划量偏差 >5% 须填写说明）；分段运单创建即生效（平台承担运输）；95306 式物流轨迹（倒序时间线 + 运输信息，约 15 秒自动刷新）；节点录入按运单状态自适应可选节点
- **履约跟踪**：五阶段履约进度条 + 节点台账（类型筛选 + 倒序轨迹，节点只增不改留痕审计）+ 运单列表
- **质检预警**：质检登记，实收数量超溢短装允差自动预警（通知需方成员钢厂与供方）
- **归档**：三条件校验（运单全部签收 + 结算完成 + 无未关闭预警），订单档案 zip 导出（含 manifest.json）

### 平台治理与风控

- **运营看板与企业准入**：企业/单据/预警多维统计；准入审批（驳回必填原因、执照在线预览、重置密码、启用停用）；**企业信息变更审核闭环**（变更暂存待审 → 运营端对比审核 → 通过自动更新 / 驳回保持不变）；资质证照在线上传
- **五类定时预警**：报价截止 / 订单超时 / 运单超时 / 质检超差 / 结算超时；同对象同类型未关闭预警唯一（AC-19 去重），预警扫描带 24h 生成节流
- **后台定时任务**：五类预警扫描、到期询价自动揭示、超时订单自动失效（含聚合订单的归集回退，间隔可配）
- **状态机集中管控**：所有单据流转经统一状态机校验，每次流转写操作日志（前后值快照）；状态字典页可视化流转路径
- **价格行情**：品种基准价按日维护（PB 粉双品位 61.5%/60.8%），多港口多品位分档展示与趋势图，钢厂端与运营端同源联动
- **消息与任务中心**：四类站内消息 + 按角色聚合的任务中心（待办/在办/已办），铃铛抽屉、点击已读跳转、未读角标

### 体验与可视化

- **UI 视觉体系**：Apple HIG 风格设计系统，毛玻璃侧栏/顶栏，令牌化主题
- **钢厂总览 / 供应商总览**：分端工作台首页（需求/订单/预警/消息核心指标与待办入口）
- **运营看板**：企业/单据/预警多维统计卡片

## 技术架构

| 层 | 技术 |
|---|---|
| 后端 | Python 3.12+（开发环境 3.14）+ Flask 3 + psycopg 3 |
| 数据库 | PostgreSQL 14（Docker 容器） |

| 后台任务 | 进程内定时扫描（五类预警：报价截止/订单超时/运单超时/质检超差/结算超时） |

## 快速开始

前提：已安装 **Docker** 与 **Python 3.12+**。

```bash
# 1. 启动 PostgreSQL 14 数据库容器（首次自动创建 mine_platform 库）
docker compose up -d

# 2. 安装 Python 依赖
pip install -r requirements.txt

# 3. 启动服务（首次运行自动建表 + 写入演示数据）
python run.py        # → http://127.0.0.1:8000
```

打开 http://127.0.0.1:8000 即可使用演示账号登录。

### 环境变量

| 变量 | 默认值 | 说明 |
|---|---|---|
| `MINE_PG_DSN` | `postgresql://postgres:Langchain2026@127.0.0.1:5432/mine_platform` | 数据库连接串 |
| `MINE_JWT_SECRET` | 内置演示密钥 | JWT 签名密钥 |
| `MINE_PORT` | `8000` | 服务端口 |
| `MINE_DISABLE_JOBS` | 未设置 | 设为 `1` 时禁用后台定时任务（五类预警扫描 / 到期询价自动揭示 / 超时订单自动失效，测试用） |
| `MINE_JOBS_INTERVAL` | `3600` | 后台定时任务扫描间隔（秒） |
| `MINE_ALERT_SCAN_INTERVAL` | `86400` | 预警扫描生成节流间隔（秒，默认 24h）：同对象同类型预警生成后该窗口内不重复产生 |
| `MINE_PG_TZ` | `Asia/Shanghai` | 数据库会话业务时区（每次连接以 `options='-c timezone=…'` 生效），保证 `now()` 生成的时间与页面展示、用户输入同一语义 |

## 使用示例

### 典型业务体验路径

1. 用 **钢厂** 账号（13800000001）登录 → 「需求管理」新建需求 → 提交进入平台归集
2. 用 **平台运营** 账号（13800000000）登录 → 「需求归集」查看钢厂需求 → 「报价询价」平台代发询价（此时才通知供应商）
3. 用 **供应商** 账号（13800000002）登录 → 「询价报价」提交 **密封报价**（截止前仅自己可见，可传报价附件）
4. 运营端揭示比价 → 各钢厂在询价详情反馈认可/不认可 → 全员认可后系统**自动锁货锁价生成聚合订单** → 供应商在「订单管理」确认订单（48h 期限）
5. 各钢厂在「订单管理」提交 **提货计划** → 全部提交后订单转「待制定运输方案」→ 运营端「运输调度」制定运输方案并创建分段运单
6. 节点上报与 95306 式物流轨迹跟踪 → 需方签收 → 归档导出

完整分角色全链路操作步骤与图文指引见 [系统使用说明](系统使用说明.md) §4（操作流程指引）。

## 常见问题（FAQ）

**Q1：启动时报数据库连接失败？**
先确认数据库容器在运行：`docker compose up -d`（或 `docker start mine-platform-pg`），再核对 `MINE_PG_DSN` 与容器端口 5432；可用 `docker logs mine-platform-pg` 排查容器状态。

**Q2：8000 端口被占用？**
通过环境变量 `MINE_PORT` 换端口启动，如 `MINE_PORT=8010 python run.py`。

**Q3：如何重置演示数据？**
清空数据库后重跑 `python run.py` 即可（建表与演示数据均幂等）；彻底重置可 `docker compose down -v` 后重新 `up -d` 并启动服务。

**Q4：注册企业后什么时候能开展业务？**
注册成功即可登录，但询价、报价、物流等业务操作需平台在「企业准入」中审核通过（APPROVED）后才可用。

**Q5：后台定时任务多久执行一次？**
默认 3600 秒（`MINE_JOBS_INTERVAL`），覆盖五类预警扫描、到期询价自动揭示、超时订单自动失效；预警生成另有 24h 节流窗口（`MINE_ALERT_SCAN_INTERVAL`），同对象同类型预警生成后 24h 内不重复产生。测试时可设 `MINE_DISABLE_JOBS=1` 关闭。

**Q6：上传的附件存放在哪里？**
本地 `uploads/` 目录（按 file_id 命名），多实例部署需改为对象存储。

**Q7：页面显示的时间与本地时间差 8 小时？**
平台业务时区统一为 Asia/Shanghai：后端对每个数据库连接设置会话时区（`backend/db.py` 的 `BUSINESS_TZ`，可用 `MINE_PG_TZ` 覆盖），容器侧已配置 `TZ/PGTZ`。若为 2026-11-08 之前初始化的存量数据库，需执行一次性迁移：`Get-Content docs\migrations\20261108_bug06_timezone_fix.sql -Raw | docker exec -i mine-platform-pg psql -U postgres -d mine_platform`；全新环境无需处理。

**Q8：生产部署有哪些注意？**
Flask 内置 WSGI 服务器仅适用于演示/开发，生产请更换（如 waitress/gunicorn）；通过环境变量注入 `MINE_PG_DSN` 与 `MINE_JWT_SECRET`，勿使用代码默认值；建议配置独立数据库账号与定期备份。

**Q9：承运商账号（13800000005）为何无法登录？**
承运商端已下线（2026-11-13 起）：仅承运商角色的账号登录会提示「本平台暂不开放承运商端登录」（业务码 40301）。运单创建与节点维护由运营端「运输调度」承担，承运商相关后端接口与数据保留。
