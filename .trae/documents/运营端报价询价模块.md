# 运营端「报价询价」模块实施计划

## Context

「需求归集」下方新增「报价询价」模块，实现平台集中采购流：**运营汇集已归集需求 → 统一向供应商发起询价 → 供应商报价 → 运营汇总报价后主动"返回钢厂端"**。约束：**只改运营端**，钢厂端/供应商端不修改。

用户已确认的决策：
1. 价格**不自动同步**钢厂：由运营端汇总供应商报价后，手动执行"返回钢厂"
2. 列表**仅显示平台代发**的询价（不做钢厂自发询价）；支持汇集多条需求明细**批量统一**发起

### 复用结论（探索依据）
- 运营端以 `buyer_id=钢厂企业id` 创建询价单后：钢厂端现有「询价报价」页天然可见（inquiry.py L120-122 按 buyer_id 过滤命中）、供应商现有报价页天然可报价（biz_inquiry_invite 校验 L235-238）——**两端零改动**
- "返回钢厂端" = 执行揭示 `reveal_inquiry(conn, iid, ctx)`（inquiry.py L308-348，无权限校验，ctx=None 先例 jobs.py L32；手动揭示接口的 deadline 校验在 API 层 L351-363，内部核心不受限）→ 揭示后钢厂端现有比价快照可见 + L360-362 自动发消息通知买方。运营端额外补一条更明确的汇总通知
- 权限障碍（绕过方式）：create/send/reveal 均 `@roles_required(ROLE_STEEL)` + 归属校验 → 在 admin.py 新增 `@plat_required` 专用接口，内部复用/参照现有 SQL，**不修改 inquiry.py 现有函数**（回归风险最低）

## 业务流

```
需求归集(SUBMITTED 明细, 剩余可询量>0)
  └─ 运营「发起询价」弹窗：多选明细(逐行数量) + 统一截止/到货日/最少响应 + 勾选供应商
       └─ 批量生成 N 张询价单(buyer_id=钢厂, source='PLATFORM', 同 batch_no, 状态 SENT)
            ├─ 供应商收到邀请 → 现有页面密封报价（供应商端不改）
            └─ 需求明细 inquired_qty 扣减、需求单转 INQUIRING（复用现有语义）
  └─ 运营「汇总报价返回钢厂」：弹窗展示全部报价汇总表 → 确认
       └─ reveal_inquiry（揭示，钢厂端比价快照可见）+ send_msg 通知钢厂
```

## 改动清单

### 一、数据库
- **docs/schema_postgresql.sql**：`biz_inquiry` 建表语句加 `source VARCHAR(16) DEFAULT 'STEEL'`（STEEL/PLATFORM）、`batch_no VARCHAR(32)`
- **backend/db.py init_schema 增量区**（L89-105 旁）：`ALTER TABLE biz_inquiry ADD COLUMN IF NOT EXISTS source VARCHAR(16) DEFAULT 'STEEL'; ADD COLUMN IF NOT EXISTS batch_no VARCHAR(32);`

### 二、后端
**backend/api/inquiry.py**（只增不改）：新增 `create_and_send_platform_inquiry(conn, buyer_id, item_row, quantity, arrive_date, deadline, min_response, supplier_ids, batch_no, remark)` —— 参照 create_inquiry 的 INSERT（L26-75）与 send_inquiry 的发出段（L89-111：DRAFT→SENT transition、扣 `inquired_qty`、需求转 `INQUIRING`、send_msg 邀请供应商 L107-110），供 admin 调用。

**backend/api/admin.py**（`@plat_required`，新增区块「报价询价」）：
1. `GET /admin/quote-inquiries`：`WHERE source='PLATFORM'` 列表（分页+状态筛选）：inquiryNo、batchNo、demandNo、companyName(钢厂)、varietyName、quantity、deadline、expectArriveDate、status、响应计数、createdAt
2. `POST /admin/quote-inquiries`：批量发起。参数 `items[]`(demandItemId+quantity)、arriveDate、deadline、minResponse、inviteSupplierIds[]、remark。校验：明细存在且 `quantity-inquired_qty >= quantity`；截止 ≥ 当前+2h（40001，沿用业务规则文案）；循环调用 inquiry.py 新函数（每单 buyer_id=明细所属需求单 company_id）
3. `GET /admin/quote-inquiries/<id>/summary`：报价汇总（biz_quote join 供应商企业名，价格升序；运营端可见，不受密封限制——运营是汇总方）
4. `POST /admin/quote-inquiries/<id>/return`：汇总返回钢厂。若未揭示 → 调 `reveal_inquiry(g.conn, iid, g.ctx)`；然后 `send_msg(钢厂, '平台报价汇总推送', '询价单 X 已汇总 N 家供应商报价并推送至贵司，请前往询价报价查看比价。', 'INQUIRY', iid)`；已揭示则仅补发通知（幂等）

**backend/api/admin.py demand_pool 小改**：行内加 `i.inquired_qty AS "inquiredQty"` 与剩余可询量（发起弹窗展示/校验用）

**backend/security.py**：`PLAT_ADMIN` menus 在 `demand_pool` 后插 `'quote_inquiry'`

**backend/seed.py**：`_ensure_platform_inquiry`（幂等，PC-DEMO 前缀）：为演示需求 XQ-DEMO-0001 明细造 1 条 PLATFORM 源 SENT 询价（2000 吨、截止=now+2天、邀请任一供应商）；`seed()` 接入
