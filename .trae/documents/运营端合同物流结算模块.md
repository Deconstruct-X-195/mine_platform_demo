# 运营端新增「合同管理 / 运输调度 / 对账结算」实施计划

## Context

「报价询价」菜单下方新增三个运营端模块（**仅改运营端代码**，钢厂/供应商/承运商端前端不动）：

1. **合同管理**：汇集各端上传的合同扫描件（复用现有签署上传），进入「待运营确认」→ 运营核验**确认即生效**纳入台账（合同库），不确认**退回上传方附原因**；台账合同与运单关联展示
2. **运输调度**：物流调度（代钢厂制定方案、匹配承运商、建运单、指派）+ 在途监控（查看轨迹、**代推进节点**：发运/到货/签收）；钢厂端零操作，现有履约跟踪页天然可见节点
3. **对账结算**：**只读统计**（不代付款不代确认）：结算单列表、金额、状态、付款进度统计

用户已确认：确认即生效 / 调度+代推进节点 / 结算仅统计。

### 探索结论（复用依据）
- 合同：`biz_contract.file_url` 存 sys_file.file_id、`file_hash` SHA-256；签署接口 `contract.py sign(:60-109)`（各端上传扫描件即此动作）；状态机 PENDING_GENERATE→PENDING_BUYER→PENDING_SUPPLIER→EFFECTIVE
- 物流：`biz_logistics_plan`（无承运商列）+ `biz_waybill`（carrier_id/段/日期/运费）+ `biz_track_node`（轨迹）；创建方案/运单/指派为 `ROLE_STEEL`（logistics.py:26/:69/:134）、节点推进 DEPART/ARRIVE 为 `ROLE_CARRIER`（:170）、签收为 buyer（track.py:70-91）；`GET /waybills`、`GET /waybills/<wid>` 已 plat 放行；承运商校验 `_check_carrier(:125-131)` 保留
- 结算：`biz_settlement` + `biz_payment`；列表/详情已 plat 全量（settlement.py:310/:343）；运营端无菜单页面
- 文件：`API.upload`→`POST /files`（files.py，白名单 pdf/jpg/png，存 uploads/ + sys_file）
- 菜单：security.py L100 `PLAT_ADMIN`、app.js `MENU_META`、css mask + sprite + ui_icons_validate（同前两模块套路）

## 业务流

```
合同：钢厂生成 → 需方签(传扫描件) → 供方签(传扫描件) → plat_status='PENDING'（合同停留待供方签状态，不自动生效）
  → 运营「核验」：确认 → transition EFFECTIVE + plat_status='CONFIRMED' 入台账 + 通知双方
              退回 → plat_status='RETURNED'+原因 → 通知最后上传扫描件方重传（重新签署后 plat_status 回 PENDING）
物流：运营选订单(PERFORMING) → 代建方案 → 建运单(选承运商→PENDING_ACCEPT / 不选→PENDING_ASSIGN)
  → 指派 → 承运商现有接单 → 运营可代推进：发运(DEPART)/到货(ARRIVE)/签收(SIGN)（钢厂端履约跟踪页天然可见节点）
结算：只读统计看板（列表 + 统计卡片 + 详情含付款记录）
```

## 改动清单

### 一、数据库（2 文件）
- **docs/schema_postgresql.sql** biz_contract 建表语句加：
  `plat_status VARCHAR(20)`（NULL=无扫描件 / PENDING=待运营确认 / CONFIRMED=已核验入台账 / RETURNED=已退回）、`plat_remark VARCHAR(500)`、`plat_confirm_by BIGINT`、`plat_confirm_at TIMESTAMP`
- **backend/db.py init_schema 增量区**：对应 `ALTER TABLE biz_contract ADD COLUMN IF NOT EXISTS ...` ×4

### 二、后端
**backend/api/contract.py sign 接口（唯一共享逻辑改动，约 3 行）**：PENDING_SUPPLIER 签署分支中，双方签齐后不再 `transition(EFFECTIVE)`，改为 `UPDATE plat_status='PENDING'`；签署通知文案加"待平台核验"。PENDING_BUYER 分支不变。

**backend/api/admin.py（`@plat_required`，3 个新区块）**：

*合同管理*：
1. `GET /admin/contracts`（分页 + platStatus 筛选）：join biz_order/ent_company×2，返回 contractNo/orderNo/buyerName/supplierName/version/双方签署时间/fileUrl/platStatus/platRemark/waybillCount（子查询 count biz_waybill by order_id）
2. `PUT /admin/contracts/<cid>/verify`：{approve, remark}。approve：仅 PENDING 可核验（40901）；`transition(biz_contract,'PENDING_SUPPLIER','EFFECTIVE')`（合同状态须为 PENDING_SUPPLIER）+ plat_status='CONFIRMED' + plat_confirm_by/at + send_msg 双方"合同已核验生效"；驳回：plat_status='RETURNED' + remark 必填 + 确定上传方（PENDING_SUPPLIER 且供方未签→需方；双方已签→supplier_sign_at 较晚者）+ send_msg 上传方"扫描件退回：原因"

*运输调度*：
3. `GET /admin/logistics-orders`：可调度订单（PERFORMING 且含合同 EFFECTIVE），带方案状态（LEFT JOIN biz_logistics_plan）
4. `POST /admin/logistics-plans`：{orderId, orgMode, remark}——参照 logistics.py create_plan SQL，`created_by=plat user`，加 biz_track_node(ORDER, PLATFORM_PLAN) + send_msg 钢厂"平台已制定物流方案"
5. `POST /admin/logistics-plans/<pid>/waybills`：{segments:[{segmentNo,transportMode,departPlace,arrivePlace,planDepartDate,planArriveDate,planQty,freight,vehicleNo?}], carrierId?}——参照 create_waybill（含 5% 偏差校验、`_check_carrier` 同规则内联校验、doc_no 'YD'），带 carrierId→PENDING_ACCEPT + send_msg 承运商；不带→PENDING_ASSIGN
6. `PUT /admin/waybills/<wid>/assign`：{carrierId}（PENDING_ASSIGN→PENDING_ACCEPT + send_msg）
7. `PUT /admin/waybills/<wid>/advance`：{action: DEPART|ARRIVE|SIGN}——按状态机推进（PENDING_DEPART→IN_TRANSIT→ARRIVED→SIGNED），UPDATE actual_depart_at/actual_arrive_at + biz_track_node(WAYBILL) + send_msg（签收时通知双方）
8. `GET /admin/waybills-ops`：调度视角运单列表（join biz_order/ent_company/carrier/biz_logistics_plan，含 contractNo）分页+状态筛选

*对账结算（只读）*：
9. `GET /admin/settlement-stats`：聚合 {total, confirmedAmount, pendingCount, paidAmount, settleAmount}
10. `GET /admin/settlements`：join ent_company×2 + 付款合计子查询，分页+状态筛选

**backend/security.py**：`PLAT_ADMIN` menus 在 `quote_inquiry` 后插 `'contract_admin','logistics_dispatch','settlement_stats'`

**backend/seed.py** `_ensure_platform_contracts`（幂等）：取一条有效订单（有合同且 PENDING_SUPPLIER 且供方未签）补 plat_status='PENDING' 演示（双方签署时间戳）；再取另一订单造 CONFIRMED 台账样例；无合适订单则跳过（不造新订单，避免连锁数据）
