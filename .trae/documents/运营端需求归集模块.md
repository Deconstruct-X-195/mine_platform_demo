# 运营端新增「需求归集」模块实施计划

## Context

运营端（PLAT_ADMIN）现有菜单：运营看板/企业准入/基础数据/单据总览/预警处理/状态字典/操作日志。需求：在「企业准入」下方新增「需求归集」模块，含两个列表：

1. **需求列表**（表格）：序号、单号、企业、品类、矿种、吨数、品位、到货日期、状态、提交日期、操作
2. **变更申请审核列表**：运营审核变更申请（通过/驳回，驳回必填原因）

用户已确认的决策：
- 变更申请**仅运营端展示+审核**，钢厂端不加发起入口；演示数据由 seed 幂等写入
- 品类数据：`base_variety` 表新增 `category` 字段，运营端品种管理可维护

关键技术现状（探索结论）：
- 菜单可见性唯一数据源：`backend/security.py` L100 `MENUS['PLAT_ADMIN']`；前端 `MENU_META`（`frontend/js/app.js` L3-26）
- 需求数据：`biz_demand`（主表，含 demand_no/version/status，**无 submitted_at**）+ `biz_demand_item`（明细：quantity/grade/variety_id）；到货日期在主表（expect_arrive_start/end）
- `base_variety` 无品类字段；`UI.STATUS` 已有 DEMAND kind（ui.js L67），无 CHANGE kind
- 建表机制：`backend/db.py init_schema()` L76-88 有**增量补建区**（CREATE TABLE IF NOT EXISTS / ALTER 幂等），老库自动补齐
- seed 幂等模式：`_ensure_*` 函数（seed.py）
- 运营接口样板：`backend/api/admin.py`（`@plat_required` + `page_args/page_data` + camelCase 别名）
- 审核接口样板：admin.py L51-70 企业审核（transition + 驳回必填 + send_msg）

## 改动清单

### 一、数据库（2 文件）

**docs/schema_postgresql.sql**（新库口径）：
- `base_variety` 建表语句加列 `category VARCHAR(50)`
- 追加新表：
```sql
CREATE TABLE biz_demand_change (
  id BIGSERIAL PRIMARY KEY,
  change_no VARCHAR(32) NOT NULL,
  demand_id BIGINT NOT NULL,
  company_id BIGINT NOT NULL,
  before_data TEXT,            -- JSON：变更前关键字段
  after_data TEXT,             -- JSON：变更后关键字段
  reason VARCHAR(500),
  status VARCHAR(20) NOT NULL DEFAULT 'PENDING',  -- PENDING/APPROVED/REJECTED
  audit_remark VARCHAR(500),
  audit_by BIGINT, audit_at TIMESTAMP,
  created_at TIMESTAMP NOT NULL DEFAULT now(), updated_at TIMESTAMP NOT NULL DEFAULT now(),
  created_by BIGINT, updated_by BIGINT, is_deleted SMALLINT DEFAULT 0,
  CONSTRAINT uk_change_no UNIQUE (change_no)
);
```
- `biz_demand` 建表语句加列 `submitted_at TIMESTAMP`

**backend/db.py `init_schema` 增量区**（老库自动补齐）：
```sql
ALTER TABLE base_variety ADD COLUMN IF NOT EXISTS category VARCHAR(50);
ALTER TABLE biz_demand ADD COLUMN IF NOT EXISTS submitted_at TIMESTAMP;
CREATE TABLE IF NOT EXISTS biz_demand_change (...同上...);
```

### 二、后端

**backend/state_machine.py**：TRANSITIONS 注册 `'biz_demand_change': {'PENDING': ['APPROVED', 'REJECTED']}`

**backend/security.py** L100：`PLAT_ADMIN` 菜单列表在 `'admin_companies'` 后插入 `'demand_pool'`

**backend/api/demand.py** `submit_demand`：新建提交与撤回重提两处写入 `submitted_at=now()`

**backend/api/admin.py**（追加 3 接口 + 品类字段）：
1. `GET /admin/demand-pool`（分页+状态筛选）：明细行展开——
```sql
FROM biz_demand_item i
JOIN biz_demand d ON d.id=i.demand_id AND d.is_deleted=0
JOIN ent_company c ON c.id=d.company_id
JOIN base_variety v ON v.id=i.variety_id
WHERE i.is_deleted=0 [AND d.status=%s]
```
返回行：demandNo、demandName、companyName、category、varietyName、quantity、grade、expectArriveStart/End、status、submittedAt（`COALESCE(submitted_at, updated_at)` 兼容存量）。
2. `GET /admin/demand-changes`（分页+状态筛选）：join ent_company + biz_demand，before_data/after_data 后端解析为 JSON 对象返回
3. `PUT /admin/demand-changes/<id>/audit`：仅 PENDING 可审（40901）；transition 状态机；驳回必填 remark；`send_msg(conn, company_id, ...)` 通知企业；op_log 留痕
4. `create_variety`/`update_variety`：支持 `category` 字段（写入/更新）

**backend/seed.py**（幂等 `_ensure_*`，在 `seed()` 调用）：
- `VARIETIES` 元组追加品类值（粉矿/块矿/精粉/球团/粉矿/混矿），`_ensure_varieties` INSERT 带上
- `_ensure_categories`：按 variety_code 幂等 UPDATE 存量品种的 category
- `_ensure_demand_changes`：无 'BG-DEMO-%' 记录时写入——先确保存在一条演示需求单（demand_no 'XQ-DEMO-0001'，示范钢铁集团，状态 SUBMITTED，1 条明细 PB粉 3000 吨品位 62.00，无则 INSERT+submit 语义），再写 3 条变更申请：2 条 PENDING（吨数 3000→3500、到货日期变更）、1 条 APPROVED、1 条 REJECTED（带审核意见）
