四、问题清单（分类 / 复现步骤 / 严重等级）

编号等级分类问题描述复现步骤根因定位
BUG-01低展示层状态字典页所有业务表恒显示"无流转"管理员→基础数据→状态字典前端 admin.js 期望行数组（from/to/event/roles），后端 TRANSITIONS 实际为 {biz:{from:[to...]}} 嵌套结构
BUG-02中前端交互新建需求明细品种下拉默认显示"PB粉"但数据未绑定，直接保存被"明细需完整填写品种/牌号/数量"拦截且原因不可见（无请求发出）新建需求→添加明细→不重选品种→保存前端 demand.js 明细 items.push({}) 未绑定默认品种
BUG-03较高前端交互编辑需求草稿时已有明细不回显（"暂无明细，请添加"），须重录明细（数据不丢，被前端兜底拦截）需求列表→草稿→编辑editForm 未载入 existing.items
BUG-04高功能阻塞需求撤回后 UI 操作列仅剩"详情"，无重提入口；API 验证 WITHDRAWN→SUBMITTED v2 成功需求提交→撤回→查看操作列前端 demand.js 仅 status==='DRAFT' 渲染提交按钮，漏 WITHDRAWN 分支
BUG-05高功能阻塞所有企业用户的"企业信息"页错误显示"平台管理员无企业档案"任意企业用户→企业信息页API /companies/me 返回平铺对象（顶层键含 company_name），前端 misc.js 读 d.company 不存在
BUG-06高时区缺陷页面按 UTC 显示业务时间，datetime-local 输入按浏览器本地时区（UTC+8）解析与校验，存在 8 小时偏移；用户按页面时间+3h 填写被"+2小时"拦截（实测 diff -4.70h）询价/报价页填写 deadline（按页面时间+3h）→保存前后端时区基准不一致：页面按 UTC 显示，datetime-local 按本地时区解析校验
BUG-07中UX/反馈询价保存被服务端校验拒绝时，toast 短暂显示后自动消失、弹窗保持打开，用户无有效反馈（"静默失败"观感）询价页填写 deadline（本地语义）→保存→观察 toast（约2-3s后消失）服务端校验拒绝 + toast 短暂自动消失 + 弹窗按设计保持打开；与 BUG-06 时区语义差耦合放大。建议：① toast 时长延长/错误摘要常驻弹窗；② 前后端时区基准统一
OBS-01观察项主数据保护品种无删除/编辑 UI 入口（后端有 PUT 无 DELETE，属主数据保护设计，PUT 编辑接口存在但 UI 未暴露）管理员→品种管理设计取舍，建议后续评估是否暴露编辑入口
OBS-02观察项设计取舍系统全量无 DELETE 端点，删除覆盖以生命周期关闭/作废等效执行（需求关闭/合同作废/预报失效）-设计取舍，非缺陷

五、测试覆盖度与结论

覆盖度：登录认证 / 企业注册准入 / 基础数据（品种·基准价·状态字典·操作日志）/ 需求申报全生命周期（草稿→提交→撤回→重提→关闭）/ 供应商需求池脱敏 / 货源资源与远期预报 / 询价→报价→揭示→议价→定标→订单→合同→物流→质检预警→结算→付款→归档导出→越权隔离，共 8 大阶段全遍历，无遗漏业务节点。覆盖度：100%（正向业务全链路）。

结论：后端数据一致性校验全部通过，业务流程主链路畅通；前端存在 2 个功能阻塞级缺陷（BUG-04 撤回后无重提入口、BUG-05 企业信息页错误提示）、1 个时区耦合缺陷（BUG-06）与若干交互/展示问题（BUG-01/02/03/07），建议按"功能阻塞→交互缺陷→展示缺陷"优先级修复。
